# [PR 244](https://github.com/MorePET/mat/pull/244) feat(optical): wavelength curves, measured surface finishes, declared absences, rs-materials 0.3.0

## Description

Grows the optical schema along the **wavelength** axis so a downstream Monte Carlo transport engine can stop sampling monochromatically at the emission peak, adds a catalogue of **measured optical interfaces**, and brings `rs-materials` up to full fidelity for the physics domains. Driven by a requirements brief from [strata](https://github.com/gerchowl/strata) (committed at `docs/briefs/strata-optical-requirements.md`); the decisions, including where we disagreed with the requester, are recorded in **ADR-0004**.

Headline additions: `WavelengthCurve` (the λ twin of `TempCurve`, clamping rather than extrapolating), wavelength accessors on `OpticalProperties`, the self-absorption split, Kubelka-Munk coefficients for diffusing reflectors, `pymat.surfaces` with 32 measured interfaces, and `Material._absent` — a way for the database to say *"we looked and the number does not exist"* rather than being silent.

Along the way it fixed **six latent defects that produced no error**, several of them years old. Those are the part of this PR most worth reviewing.

## Additional Notes

### Six defects that produced no error

| Defect | How long it had been there |
|---|---|
| `[esr.optical] reflectivity = 98.5` parsed then discarded — no field existed to receive it | since #147 |
| Four more silently-dropped keys (`dopant`, `dopant_pct`, `flammable`, `toxic`) + one filed under the wrong group | various |
| Every **root** material lost its `grade`/`temper`/`treatment`/`vendor` to an operator-precedence bug | long-standing |
| `sources.py` alias pointed `radiation_length` at `optical.*` after #157 moved it to `nuclear` | since #157 |
| Rust replaced child `tags` over the parent's instead of unioning them | since the crate existed |
| Enricher-appended keys filed past a section banner, awaiting capture by the next adjacent insert | since #164 |

None of these raised. A value can be cited, committed, reviewed — and still not be there.

### ⚠️ Two deliberate behaviour changes

`loader.py` wrote `grade or parent.grade if parent else None`, which Python parses as `(grade or parent.grade) if parent else None`. With no parent the expression collapsed to `None`, so **every root material silently discarded its own `grade`, `temper`, `treatment` and `vendor`**. `pymat.beryllium.grade` was `None` despite the TOML declaring `"S-200F"`; `pymat.esr.vendor` was `None` despite `"3M"`. Eleven grades and six vendors across the corpus.

This is a fix, but it **changes values a consumer could already read**. Anything relying on those being `None` will see real strings now.

**2. `lyso.Ce.saint_gobain.prelude420` light yield: 34000 → 33200 ph/MeV.**

The Luxium (formerly Saint-Gobain Crystals) PreLude 420 data sheet states
33200. The 34000 on disk was an uncited round-up, and the value now carries
that citation. A consumer already reading
`pymat.lyso.Ce.saint_gobain.prelude420.properties.optical.light_yield` will get
a different number.

Caught by CI rather than locally: the test pinning it is gated behind
`importorskip("build123d")`, which pins `python_version < '3.13'`, and this
machine is on 3.13 — so the local suite skips 64 tests where CI skips 54.
Flagged here because a reviewer spotted it was missing from this list, not
because I remembered it.

### Review

Blocked on first review for a real defect: `km_split_at` exposed a
`backing_reflectance` parameter that returned **negative absorption** for any
`Rg > 0`, while its docstring claimed the tuple summed to 100 "by
construction". The sum held — `A` was *defined* as the remainder — but the
interpretation did not, because with a backing K-M's `R` is the composite
reflectance while `T` is the layer's own. The parameter is removed rather than
repaired; there is no consumer for it and no correct decomposition worked out.

The single test touching it asserted `bright > black`, an **ordering** property,
which passes throughout the defect. Replaced with a conservation sweep.

### `rs-materials` 0.3.0

`OpticalProperties` went from four `Option<f64>` scalars to the full physics set; `NuclearProperties`, `MechanicalProperties` and `ThermalProperties` were added, along with curves, uncertainty, `_sources` and `_absent`. `manufacturing`/`compliance`/`sourcing`/`vis` are deliberately **not** mirrored — `Material::raw()` reaches them instead, which is a guarantee where parity would have been a promise (ADR-0004 §7).

Two parser bugs fixed there: inheritance consulted only one ancestor level, and property groups were replaced wholesale rather than merged key-by-key. Both now tested.

**Breaking for Rust consumers** (method signatures gained parameters, `formula` no longer inherits). Pre-1.0, so the minor bump carries it; strata is pinned to 0.2 and waiting on publication.

### New gates

- `scripts/check_data_shape.py` — pre-commit hook for the dropped-key and misfiled-key classes above. Stdlib-only (parses `properties.py` with `ast`), and the tests call the script so there is one implementation rather than two.
- `scripts/mutation_audit.py` — repeatable, not wired to CI (runs the suite ten times).
- `tests/test_rs_python_parity.py` — runs in the `rust` CI job, the only one with both toolchains.

### Scope deliberately refused

Three requests were declined and the reasoning is in ADR-0004: a fitted scattering coefficient (a fit against one module measures that module), `default_surface` on a material (which finish a crystal is wrapped in is a fact about a built detector), and `contact.grease_sipm` (a pairing of two materials that each already carry their own numbers). A test pins the absence of the third so the reasoning cannot be quietly reversed.

The requester later retracted the fit that motivated the first refusal — it contained an arithmetic error, and accepting it would have entered a manufactured constant into this corpus as cited data.
